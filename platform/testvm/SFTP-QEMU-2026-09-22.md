# Native SFTP confinement qualification

2026-09-22, retained Ubuntu ARM64 QEMU; isolated source at
`/home/harness/lanes/access/platform`. No production SSH configuration, listener,
or service was modified. No native/vendor source or capabilities were changed.

## Reproduced failures

The previous `ApplyAccessGrant` reported success but wrote the site's public key
file root-owned `0600`: actual OpenSSH rejected login with `Permission denied`
while reading that key file. It also emitted no per-principal chroot or forced
SFTP command. A first descriptor-bind implementation using `nsenter` passed as
unrestricted root but failed under the executor capability bound: opening
`/proc/1/ns/mnt` was denied. That implementation was removed.

## Qualified behavior

`TestNativeSFTPGrantRootIsolation` passes through native `sftp` and a separately
listening loopback `/usr/sbin/sshd`, with pinned ephemeral host key. Both
read/write and read-only cases run under a disposable systemd unit matching the
executor's relevant namespace and capability restrictions. Final native run:
5.68 seconds; both subtests passed.

- Allowed-root binary download preserves exact bytes, including NUL and `0xff`.
- Read/write upload preserves those bytes; read-only upload is denied.
- Known unique second-site content (UID/GID 62172) is inaccessible through an
  absolute host path or symlink; host `/etc/passwd`, `..`, and escaping symlinks
  are also denied.
- A foreign-owned source directory is rejected before account/mount creation.
- Injected native reload failure leaves no authorized key, account, or mount.
- A conflicting root for the same site/principal is rejected.
- A pre-existing final `Match` block does not capture the managed include;
  unrelated SSH principal retains `ChrootDirectory none`/`ForceCommand none`.
- Reapply succeeds. Explicit mount removal followed by reconciliation restores
  the exact authorized root. Source and mounted inode/device are verified before
  authorization is published.
- Revoke terminates an already-open SFTP session and denies the next login.
  Repeated revoke succeeds; reconciliation does not revive the account.
- Native sshd rejects an expired rendered key; fresh-executor reconciliation
  after mount loss removes it rather than remounting. The read-only case also
  exercises the normal no-expiry grant.

Session termination uses pidfds, not an observation-then-kill PID. Selection is
anchored to a root-owned exact-login SSH privilege monitor and its matching
UID/parent/login child, never all processes sharing a site's UID.

## Reproduction (QEMU only, reserve native fixture lease first)

The test reserves disposable UID/GID 62171, verifies 62172 is unused, creates
unique fixture paths and an SFTP-only duplicate-UID login, and removes its
accounts, keys, mounts, and directories. Do not run this fixture concurrently.

```sh
cd /home/harness/lanes/access/platform
sudo env GOMAXPROCS=1 GOPATH=/home/harness/gopath \
  GOCACHE=/home/harness/.cache/go-build GOPROXY=off GOSUMDB=off \
  /home/harness/go/bin/go test -p 1 -c \
  -o /var/lib/cyberpanel/sftp-proof.test ./internal/access
sudo systemd-run --unit=cyberpanel-sftp-proof --wait --pipe --collect \
  --setenv=CYBERPANEL_QEMU_SFTP=1 \
  -p UMask=0027 -p NoNewPrivileges=true -p PrivateTmp=true -p PrivateDevices=true \
  -p ProtectSystem=strict -p ProtectHome=tmpfs -p RestrictNamespaces=~cgroup \
  -p 'CapabilityBoundingSet=CAP_CHOWN CAP_DAC_OVERRIDE CAP_FOWNER CAP_FSETID CAP_KILL CAP_SETGID CAP_SETUID CAP_NET_ADMIN CAP_SYS_ADMIN CAP_SYS_CHROOT CAP_MKNOD CAP_AUDIT_WRITE' \
  -p AmbientCapabilities=CAP_SETUID \
  -p 'ReadWritePaths=/etc /var/lib/cyberpanel /run/cyberpanel' \
  /var/lib/cyberpanel/sftp-proof.test \
  -test.run TestNativeSFTPGrantRootIsolation -test.count=1 -test.v
```

Normal package checks use offline `go test -p 1` for `./internal/access`,
`./internal/apiserver`, and `./cmd/cyberpanel`. The existing root-only installer
tests in the last package require `TMPDIR=/root`; `/tmp` is intentionally
rejected as an unsafe configuration ancestor.
